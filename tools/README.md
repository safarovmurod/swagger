# Генератор фотографий товаров

Каждому из 780 товаров — своя студийная фотография на белом фоне.
Раньше на весь сайт было 2 фото, и коляска стояла в категории «Кроватки».

## Как это работает

Товары одной подкатегории однотипны и отличаются только цветом и
материалом, поэтому фото делаются не по одному, а сеткой-контактным
листом: одна генерация 4800×3584 = 20 фотографий одной подкатегории.
Сетка режется на отдельные квадраты, каждый сохраняется под именем
`slug.jpg`. Так на 780 товаров нужно 39 генераций вместо 780.

Сетка задаётся строго как 5 колонок × 4 ряда на холсте 4:3 — на таком
холсте модель воспроизводит запрошенную решётку точно. Число ячеек
всё равно проверяется по факту: границы находятся по проекциям
небелых пикселей, а не берутся на веру.

## Файлы

| файл | назначение |
|---|---|
| `lexicon.js` | русские данные каталога → английские термины промпта: цвета (28), материалы (49), возраст (19), объект по подкатегории и «Типу» (122 описания, 0 пропусков) |
| `references.json` | образцы формы товара по подкатегориям (из ZIP и фото из чата) |
| `build-plan.js` | `plan.json`: 780 товаров → 39 сеток, промпт каждой сетки, имя файла каждого товара |
| `slice_grid.py` | режет сетку на квадраты 800×800 JPEG q82 с полем 7 % |
| `ingest.js` | принимает скачанную сетку, раскладывает файлы, ведёт `state.json` и печатает отчёт `id \| slug \| готово` |

## Порядок для одной подкатегории

```bash
node tools/build-plan.js                       # план (уже собран)
node -e "…"                                    # взять b.gridPrompt нужной сетки
# сгенерировать сетку 4:3 4k по этому промпту, скачать в work/grids/<sub>.png
node tools/ingest.js <sub> work/grids/<sub>.png
node tools/ingest.js --status                  # сколько готово
node tools/ingest.js --todo                    # какие подкатегории остались
```

## Отдача картинок

`lib/handlers/images.js` сначала ищет `assets/products/{slug}.jpg`
(`?variant=2` — второй ракурс из `assets/products/v2/`), и только если
фото нет — рисует прежнюю SVG-заглушку. Расширение `.svg` в URL
оставлено намеренно: исходные данные не меняются, поэтому ни один
работающий клиент не ломается — меняется только `Content-Type`.
