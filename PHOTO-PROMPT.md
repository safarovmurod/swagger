# Промт для бота, который делает фотографии товаров

Ниже — готовый текст задания. Копируйте его целиком, от строки «Задача» и до
конца файла, и отдавайте боту одним сообщением. Ничего дописывать не нужно:
там есть и список товаров, и требования к кадру, и правила приёмки.

---

## Задача

В каталоге интернет-магазина «Карапуз» 780 товаров. У 120 фотографии уже есть,
остальным **660 нужны настоящие снимки**: сейчас вместо фотографии показывается
нарисованная карточка. Нужно, чтобы у каждого товара была фотография **именно
того предмета, который написан в названии**, и чтобы весь каталог смотрелся
как съёмка одного магазина, а не сборная солянка.

Репозиторий: `safarovmurod/swagger`, папка с фотографиями — `assets/products/`.

## Шаг 1. Возьми список товаров

Из корня репозитория:

```bash
node -e "
const { products } = require('./lib/data');
const need = products.filter(p => !String(p.image).includes('/assets/products/'));
const rows = need.map(p => [p.slug, p.name, p.brand, p.country, p.categoryName,
  p.subcategoryName, (p.colorOptions || []).join('|'), (p.materials || []).join('|'),
  p.ageGroup].join('\t'));
require('fs').writeFileSync('photos-todo.tsv',
  'slug\tname\tbrand\tcountry\tcategory\tsubcategory\tcolors\tmaterials\tage\n' + rows.join('\n') + '\n');
console.log('осталось снять:', rows.length);
"
```

Получится `photos-todo.tsv` — 660 строк, по одной на товар. Колонки:

| колонка | что это | как использовать |
|---|---|---|
| `slug` | адрес товара | **имя файла фотографии** |
| `name` | название | главное: что именно в кадре |
| `brand`, `country` | бренд и страна | только для стиля, в кадр не попадают |
| `category`, `subcategory` | раздел каталога | уточняет тип предмета |
| `colors` | цвета через `\|` | берём **первый** |
| `materials` | материалы через `\|` | фактура: дерево, пластик, ткань |
| `age` | возраст ребёнка | размер и тип модели |

`photos-todo.tsv` — рабочий файл, в репозиторий его класть не нужно.

## Шаг 2. Как называть файлы

Ровно так: `assets/products/{slug}.jpg`.

```
slug: pelenalnyy-komod-papaloni-bambino-121
файл: assets/products/pelenalnyy-komod-papaloni-bambino-121.jpg
```

Никаких `-1`, `-copy`, `-final`, никаких заглавных букв, пробелов и других
расширений. Имя файла — единственное, что связывает фотографию с товаром:
ошиблись в имени — фотография не подключится, и её никто не увидит.

## Шаг 3. Каким должен быть кадр

- **один товар целиком**, по центру, ничего лишнего рядом;
- **фон чисто белый**, мягкая естественная тень под предметом;
- ровный студийный свет, без резких бликов и цветной подсветки;
- ракурс три четверти, предмет виден полностью и не обрезан краями кадра;
- **квадрат 1:1, 800×800** (можно рисовать крупнее и уменьшать);
- **JPEG**, качество ~85, вес **до 80 КБ** (у готовых 120 файлов — 20–40 КБ);
- образец стиля — уже лежащий в репозитории
  `assets/products/kolybel-chicco-nanny-91.jpg`. Новые кадры должны стоять
  рядом с ним и выглядеть как один каталог.

## Шаг 4. Фотография обязана совпадать с названием

Это главное требование. Проверяй по строке из `photos-todo.tsv`:

- **тип предмета** — из названия и подкатегории. «Пеленальный комод» — это комод
  с бортиками, а не кроватка; «Бустер» — это сиденье без спинки, а не автокресло
  группы 0+; «Молокоотсос» — не бутылочка;
- **цвет** — первый из колонки `colors`. Написано «Орех» — комод цвета ореха,
  а не белый;
- **материал** — из колонки `materials`: массив бука должен выглядеть деревом,
  ЛДСП — ламинированной плитой, пластик — пластиком;
- **возраст** — из колонки `age`: 0–6 месяцев это люлька, 3–7 лет — бустер;
- **бренд и страна** — только настроение и уровень модели. **Логотипов, надписей
  и фирменных знаков в кадре быть не должно.**

## Шаг 5. Промт для генератора изображений

Шаблон, подставляй значения из строки TSV:

```
Студийная предметная фотография: {name}.
Категория: {category} → {subcategory}. Цвет: {первый из colors}.
Материал: {первый из materials}. Для ребёнка {age}.
Один предмет целиком в центре кадра, ракурс три четверти, чистый белый фон,
мягкая тень под предметом, ровный рассеянный свет, высокая детализация,
каталожная съёмка интернет-магазина, квадратный кадр 1:1.
Без людей, без рук, без текста, без логотипов, без водяных знаков,
без коллажа, без рамок и подписей.
```

То же по-английски — многие генераторы понимают его точнее:

```
Studio product photo of {name in English or transliterated}, a {subcategory} for
a {age} child, {color} color, made of {material}. Single object centered,
three-quarter view, pure white seamless background, soft natural shadow under the
object, even diffused studio light, sharp focus, high detail, e-commerce catalog
shot, square 1:1 framing.
Negative: people, hands, baby, text, letters, logo, watermark, price tag, collage,
multiple views, frame, border, transparent background, blurry, distorted.
```

Три заполненных примера:

```
Студийная предметная фотография: Пеленальный комод Papaloni Bambino.
Категория: Детская мебель → Пеленальные комоды. Цвет: орех. Материал: массив бука.
Для ребёнка 0–5 лет. Один предмет целиком в центре кадра, ракурс три четверти,
чистый белый фон, мягкая тень, ровный рассеянный свет, каталожная съёмка, 1:1.
```

```
Студийная предметная фотография: автокресло группы 2-3 (бустер со спинкой).
Категория: Автокресла → Группа 2-3. Цвет: серый. Материал: текстиль и пластик.
Для ребёнка 3–12 лет. Один предмет целиком, ракурс три четверти, чистый белый фон,
мягкая тень, ровный рассеянный свет, каталожная съёмка, 1:1.
```

```
Студийная предметная фотография: молокоотсос электрический.
Категория: Кормление → Молокоотсосы. Цвет: белый. Материал: пластик и силикон.
Для ребёнка 0–12 месяцев. Один предмет целиком, ракурс три четверти, чистый белый
фон, мягкая тень, ровный рассеянный свет, каталожная съёмка, 1:1.
```

## Чего в кадре быть не должно

Люди, руки, дети · текст, буквы, цифры, логотипы, водяные знаки, ценники ·
коллаж и несколько ракурсов в одном кадре · интерьер и реквизит, не относящийся
к товару · рамки и скруглённые углы · прозрачный фон · размытие и искажения.

## Шаг 6. Как сдавать работу

1. Клади файлы прямо в `assets/products/`. **Только `*.jpg`.** Служебные папки,
   кэш, исходники, архивы, файлы моделей и всё, что весит десятки мегабайт,
   в репозиторий не попадают — их приходится вычищать вручную.
2. Работай пачками по 50–100 фотографий, а не всеми 660 сразу: так ошибку стиля
   видно на первой пачке, а не в конце.
3. После каждой пачки из корня репозитория:

   ```bash
   npm run generate   # переключает ссылки товаров на новые файлы
   npm run check      # проверяет данные, картинки и спецификацию
   npm run test:api   # сквозная проверка эндпоинтов
   ```

   Обе проверки должны быть зелёными. Только после этого коммит.
4. Если фотография какого-то товара не получилась — **лучше не класть файл вовсе**.
   Тогда у товара останется нарисованная карточка, и каталог не сломается.
   Плохая фотография хуже, чем её отсутствие.

## Как проверить себя

```bash
node -e "
const fs = require('fs');
const { products } = require('./lib/data');
const slugs = new Set(products.map(p => p.slug));
const files = fs.readdirSync('assets/products');
const wrong = files.filter(f => !f.endsWith('.jpg') || !slugs.has(f.replace(/\.jpg$/, '')));
const heavy = files.filter(f => fs.statSync('assets/products/' + f).size > 80 * 1024);
console.log('файлов:', files.length, 'из 780');
console.log('имя не совпадает со slug:', wrong.length, wrong.slice(0, 10));
console.log('тяжелее 80 КБ:', heavy.length, heavy.slice(0, 10));
"
```

Всё три числа должны быть в порядке: файлов столько, сколько снял, лишних имён
нет, тяжёлых нет.
