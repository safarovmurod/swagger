# Карапуз API

Учебный REST API интернет-магазина детских товаров: каталог, блог, отзывы,
регистрация с загрузкой фотографии и страница «Личные данные».

**Swagger UI:** `/` (она же `/swagger`) · **Каталог по категориям:** `/docs` ·
**Спецификация:** `/api/swagger.json`

Это тренажёр для практики, а не боевой магазин: читать и менять данные можно
без токена и без входа, проверок на форме регистрации нет, а личные данные
наружу уходят закрытыми звёздочками.

## Формат ответа

У каждого ответа один конверт — `data`, `errors`, `statusCode`:

```js
const { data } = await axios.get('https://swagger-wheat.vercel.app/api/products?pageSize=20');
data.data.map(p => p.name);   // data — массив, сразу готов к перебору
data.totalCount;              // 780
data.errors;                  // []
data.statusCode;              // 200
```

| Ответ | Тело |
|---|---|
| Список | `{ "data": [ … ], "errors": [], "statusCode": 200, "totalCount": 780, "page": 1, "pageSize": 20, "totalPages": 39, "hasPrevious": false, "hasNext": true }` |
| Одна запись | `{ "data": { "id": 11, … }, "errors": [], "statusCode": 200 }` |
| Ошибка | `{ "data": null, "errors": ["Товар 999 не найден"], "statusCode": 404 }` |

**Где `data` — массив.** Везде, где эндпоинт отдаёт список: `/api/products`,
`/api/categories`, `/api/subcategories`, `/api/blog`, `/api/promotions`,
а также каталог и отзывы — `/api/avtokresla`, `/api/avtokresla/gruppa-1`,
`/api/categories/{id}`, `/api/subcategories/{id}`, `/api/products/{id}/reviews`.
В этих ответах описание категории и подкатегории лежит рядом с массивом,
в полях `category` и `subcategory` — отдельный запрос за описанием не нужен.

```js
const { data } = await axios.get(`${API}/avtokresla/gruppa-1`);
data.data.map(p => p.name);        // товары подкатегории
data.subcategory.description;      // описание подкатегории
data.category.info.howToChoose;    // справка по категории
```

**Где `data` — объект.** Только у одиночных записей: `/api/products/{id}`,
`/api/blog/{id}`, `/api/promotions/{id}`, а также у ответов POST, PUT и DELETE.

Единственное исключение из конверта — `/api/swagger.json`: это сама
спецификация OpenAPI, её оборачивать нельзя, иначе её перестанут понимать
Swagger UI, Postman и генераторы клиентов.

## Эндпоинты

Читаемые адреса каталога — по ним же работает страница документации:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/{category}` | категория целиком: `/api/avtokresla`, `/api/kolyaski` |
| GET | `/api/{category}/{subcategory}` | подкатегория и её 20 товаров: `/api/avtokresla/gruppa-1` |

Оба возвращают описание, справку `info` и подкатегории в том же ответе — отдельный
запрос за описанием не нужен.

| Метод | Путь | Назначение |
|---|---|---|
| GET POST | `/api/categories` | список категорий с подкатегориями · создание |
| GET PUT PATCH DELETE | `/api/categories/{id}` | категория по id или slug + её товары |
| GET | `/api/categories/{id}/products` | только товары категории, с фильтрами |
| GET POST | `/api/subcategories` | плоский список подкатегорий · создание |
| GET PUT PATCH DELETE | `/api/subcategories/{id}` | подкатегория + массив её товаров |
| GET POST | `/api/products` | каталог с фильтрами, поиском и сортировкой · создание |
| GET | `/api/products/search` | поиск: `?q=Nuovita` |
| GET | `/api/products/filter` | те же фильтры отдельным адресом |
| GET | `/api/products/slug/{slug}` | товар строго по slug |
| GET PUT PATCH DELETE | `/api/products/{id}` | карточка товара + похожие |
| GET POST | `/api/products/{id}/reviews` | отзывы товара · добавление отзыва |
| GET | `/api/reviews` | все отзывы каталога в одном списке |
| GET PATCH DELETE | `/api/reviews/{id}` | один отзыв: правка и удаление |
| GET POST | `/api/promotions` | список акций · создание |
| GET PUT PATCH DELETE | `/api/promotions/{id}` | одна акция: полный текст + её товары |
| GET POST | `/api/blog` | статьи блога · создание |
| GET PUT PATCH DELETE | `/api/blog/{id}` | статья по id или slug, с соседними и похожими |
| GET | `/api/blog/slug/{slug}` | статья строго по slug |

Фильтры `/api/products`: `search` (он же `q`), `categoryId`, `categorySlug`,
`subcategoryId`, `subcategorySlug`, `onlyPromo` (он же `isPromo`), `isNew`,
`inStock`, `brand`, `country`, `color`, `material`, `ageGroup`, `priceMin`
(он же `minPrice`), `priceMax` (он же `maxPrice`), `ratingMin` (он же `minRating`),
`sort`, `sortBy`, `sortDir`, `light`, `page`, `pageSize`. Списки (`brand`, `color`,
`material`, `country`, `ageGroup`) принимают значения через запятую. Параметр
`light=true` отдаёт короткие карточки без отзывов и характеристик.

Сортировка записывается двумя способами: коротко одним параметром
`?sort=price_asc` (ещё `price_desc`, `name_asc`, `name_desc`, `newest`, `rating`,
`discount`, `popularity`) или подробно — `?sortBy=price&sortDir=asc`.
Один и тот же набор фильтров работает у `/api/products`, `/api/{category}`,
`/api/{category}/{subcategory}`, `/api/categories/{id}/products` и
`/api/subcategories/{id}` — раньше каждый из них понимал свой обрезанный набор.

`page` и `pageSize` не ломаются от мусора: `abc`, `-5`, `0` и `1000000`
приводятся к значениям по умолчанию (1 и 20) и к потолку 200, ответ остаётся 200.

`{id}` у категорий, подкатегорий, товаров и акций принимает и число, и slug:
`/api/categories/kolyaski`, `/api/promotions/akciya-avtokresla`.

## Аккаунт — два запроса

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/users` | создать аккаунт **или** сохранить изменения |
| DELETE | `/api/users/{id}` | удалить аккаунт |
| GET | `/api/users/{id}/avatar` | сам файл фотографии — вставляется в `<img src>` |

Один POST делает обе вещи:

- **без `id`** → создаётся новый аккаунт (это регистрация), ответ `201`;
- **с `id`** → сохраняются изменения этого аккаунта, ответ `200`.

`id` можно прислать в теле запроса или прямо в адресе — `POST /api/users/7`
работает так же. Студент пишет одну функцию с `FormData` и переиспользует её
на обеих страницах.

**Массив полей ровно такой:**

```
fullName   tel   email   password   address   avatar
```

**Проверок нет.** Любая почта, любой пароль, любое имя — и пустые поля тоже:
форма должна отправляться с первого раза, а не спорить со студентом. Массив
приходит целиком, просто с пустыми значениями.

**Личные данные закрыты звёздочками.** Тренажёр открыт всем, чужую регистрацию
может прочитать кто угодно, поэтому наружу уходит неполное значение:

| Поле | Что видно |
|---|---|
| `fullName` | `Ма*****` |
| `tel` | `+9929001*****` — последние пять цифр закрыты |
| `email` | `saf*****@gmail.com` — домен виден, он не секрет |
| `address` | `Душ*****` |

Форма «Личные данные» заполняется этими же закрытыми значениями и при сохранении
возвращает их на сервер. Это учтено: **значение со звёздочками не записывается**,
остаётся прежнее. Меняется только то, что ввели заново, а какие поля пропущены —
видно в поле `unchanged` ответа.

**`id` сохраните.** Он приходит в ответе и нужен, чтобы потом сохранять изменения
и удалить аккаунт. Обычно его кладут в `localStorage`.

**Фотография.** Принимается снимок с телефона до 10 МБ. Сервер сам обрезает его
по центру в квадрат и сжимает до 512×512 JPEG — в базе лежат килобайты, а не
мегабайты, и круглая маска в профиле не срезает лицо. Тип определяется по первым
байтам файла, поэтому `shell.php`, переименованный в `.png`, не пройдёт.

> На Vercel запрос больше **4.5 МБ** не пропускает сама платформа — это её
> ограничение, из кода его не обойти. Локально и на других хостингах работают
> все 10 МБ.

**Сколько аккаунтов живёт.** Последние 50 регистраций; когда появляется 51-я,
самая старая удаляется сама. Так открытый тренажёр не разрастается.

**Кто что может.** Токен не нужен нигде: `POST`, `PUT`, `PATCH` и `DELETE`
каталога работают без входа. Единственное правило — **чужое трогать нельзя**:
если при создании записи вы передали `userId`, то менять и удалять её можно
только с тем же `userId`, иначе `403`. Записи из готового каталога владельца
не имеют и открыты всем.

```js
// создали товар от своего имени
await axios.post('/api/products', { name: 'Коляска', price: 12000, userId: 7 });

// удалить сможет только userId=7
await axios.delete('/api/products/781?userId=7');   // 200
await axios.delete('/api/products/781?userId=9');   // 403
```

Если строгий режим всё-таки нужен, `ADMIN_WRITES=true` возвращает поведение
«менять данные может только администратор с токеном».

## Как это отправить из фронтенда

Регистрация и «Сохранить изменения» — одна и та же функция с `FormData`.
Свой `Content-Type` ставить нельзя, границы расставляет браузер.

```js
// одна функция на обе страницы
function saveUser(fields, photo, id) {
  const form = new FormData();
  Object.entries(fields).forEach(([key, value]) => form.append(key, value));
  if (photo) form.append('avatar', photo);
  if (id) form.append('id', id);
  return axios.post('https://swagger-wheat.vercel.app/api/users', form);
}
```

```js
// страница «Регистрация» — без id
const { data } = await saveUser({
  fullName: 'Мансур',
  tel: '+992900123456',
  email: 'safarov@gmail.com',
  password: 'ExamplePassword123!',
  address: 'Душанбе'
}, fileInput.files[0]);

localStorage.setItem('userId', data.data.id);   // ← пригодится дальше
```

```js
// страница «Личные данные» — с id
const id = localStorage.getItem('userId');
await saveUser({ fullName: name, tel, address }, photo, id);
```

`fetch` работает так же — разницы нет:

```js
await fetch('/api/users', { method: 'POST', body: form });
```

Удалить аккаунт:

```js
await axios.delete(`/api/users/${id}`);
```

## Хранилище и переменные окружения

Все настройки необязательны: без единой переменной проект запускается и работает.

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | строка подключения PostgreSQL. Пусто — аккаунты живут в памяти инстанса |
| `MAX_USERS` | сколько регистраций держим, по умолчанию 50 |
| `MAX_AVATAR_BYTES`, `MAX_BODY_BYTES` | потолки размера фотографии и запроса |
| `ADMIN_WRITES` | `true` — строгий режим: менять данные может только администратор |
| `JWT_SECRET`, `JWT_EXPIRES_IN` | подпись и срок токена. Токен обязателен только в строгом режиме |
| `ALLOWED_ORIGINS` | список доменов через запятую вместо `*` |
| `RATE_LIMIT_WINDOW`, `RATE_LIMIT_AUTH`, `RATE_LIMIT_WRITE`, `RATE_LIMIT_READ` | ограничение частоты запросов |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`, `ADMIN_TEL` | демонстрационный администратор |

Полный список с пояснениями — в `.env.example`. Файл `.env` в репозиторий
не попадает, реальные значения храните у себя и в настройках Vercel.

**Где взять `DATABASE_URL` бесплатно.** Пока переменной нет, регистрация работает,
но созданные аккаунты пропадают при холодном старте функции. Чтобы они жили
постоянно:

1. Откройте [neon.tech](https://neon.tech) и войдите через GitHub.
2. **Create project** — любое имя, регион поближе.
3. На экране проекта найдите **Connection string**.
4. Выберите вариант **Pooled connection** — он рассчитан на serverless.
5. Скопируйте строку целиком (начинается с `postgresql://`) и добавьте её
   в Vercel: **Project → Settings → Environment Variables → DATABASE_URL**,
   затем **Redeploy**.

Тот же путь через сам Vercel: **Storage → Create Database → Postgres** — тогда
переменная появится в проекте автоматически. Таблицы (`users`, `user_avatars`,
`revoked_tokens`) создаются при первом обращении, миграции запускать не нужно.

Каталог, блог и акции остаются в `lib/dataset.json`: это витрина для практики,
а не склад. Изменения каталога через POST/PUT/PATCH/DELETE живут до перезапуска
инстанса — так же, как было раньше.

## Безопасность

Профессиональный базовый уровень, без обещаний стопроцентной защиты:

- пароли — `scrypt`, сравнение хешей за постоянное время; ни пароль, ни его хеш
  не появляются ни в одном ответе;
- личные данные наружу уходят закрытыми звёздочками;
- ограничение частоты запросов с заголовками `X-RateLimit-*` и `Retry-After`;
- ограничения размера запроса и файла, тип картинки определяется по её первым
  байтам, а не по имени и не по заголовку;
- чужую запись нельзя изменить и удалить (`userId` владельца);
- CORS: `*` по умолчанию, список доменов — через `ALLOWED_ORIGINS`;
- заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`;
- 500 наружу отдаёт только «Внутренняя ошибка сервера» — стек, пути и настройки
  окружения остаются в логах сервера.

## Ошибки

Конверт тот же, что и у успешного ответа, плюс разбираемый блок `error`:

```json
{
  "data": null,
  "errors": ["Некорректные данные"],
  "statusCode": 400,
  "message": "Некорректные данные",
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные данные",
    "details": [{ "field": "email", "message": "Некорректный email" }]
  }
}
```

Коды: `VALIDATION_ERROR`, `UNAUTHORIZED`, `INVALID_TOKEN`, `TOKEN_REVOKED`,
`INVALID_CREDENTIALS`, `FORBIDDEN`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `CONFLICT`,
`EMAIL_ALREADY_EXISTS`, `TEL_ALREADY_EXISTS`, `REVIEW_ALREADY_EXISTS`,
`PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `TOO_MANY_REQUESTS`, `INTERNAL_ERROR`.
Поля `errors` и `message` остались на месте — старый код читать ответы не разучился.

## Тексты

Тексты не шаблонные — у каждой категории свои:

- **`category.info`** — блок справки: `note`, `howToChoose`, `delivery`, `warranty`, `payment`.
  У мебели это про замеры комнаты и сборку, у автокресел — про краш-тесты и вес ребёнка,
  у одежды — про размеры в сантиметрах, у гигиены — про сроки годности и объёмы упаковок.
- **`subcategory.description`** — своё описание у каждой из 37 подкатегорий.
- **`promotion.content`** — своя акция у каждой категории: свой заголовок, сроки, условия
  и то, что к ней прилагается (бесплатная сборка мебели, проверка установки автокресла,
  примерка одежды при курьере, проверка срока годности питания).
- **`blog[].content`** — 24 статьи с настоящим текстом на 870-1350 символов: прикорм,
  выбор коляски и автокресла, подготовка детской, гигиена новорождённого, список
  в роддом, размеры одежды, подгузники, стульчик, зимние прогулки. У каждой статьи
  свой slug, обложка и вторая иллюстрация внутри текста, выделенная цитата, теги,
  дата, время чтения и категория каталога.

Тексты категорий и акций лежат в `lib/copy.js`, статьи блога — в `lib/blog-posts.json`.
`npm run check` падает, если два текста совпали, если статей меньше 24, если статья
короче 600 символов или у неё нет второй иллюстрации, цитаты и тегов.

## Страницы

**`/` — настоящий Swagger UI.** Файлы лежат в репозитории (`assets/swagger`),
а не на чужом CDN, поэтому страница открывается даже когда внешние домены
недоступны. Разделы, «Try it out», форма с кнопкой «Choose File» у регистрации,
готовые примеры запросов — всё как в привычном Swagger.

Все ссылки одним списком лежат в [LINKS.md](LINKS.md) — по одной строке на
запрос, под каждой написано, что она вернёт (`npm run links` пересобирает).

Раздел **«Каталог»** перечислен поимённо: `GET /api/detskaya-mebel` — «Детская
мебель — вся категория», `GET /api/detskaya-mebel/krovatki` — «Детская мебель →
Кроватки», и так все 8 категорий и 39 подкатегорий. Видно, какой запрос что
вернёт, ещё до нажатия. В разделе **«Аккаунт»** показан один `POST /api/users`
с единственной формой `multipart/form-data`; `DELETE /api/users/{id}` и
`GET /api/users/{id}/avatar` работают, но на странице не показаны.

**`/docs` — каталог по категориям.** Страница построена вокруг данных,
а не вокруг списка методов:

- **Блок на каждую категорию.** Нажали «Автокресла» — внутри 7 готовых
  GET-запросов: вся категория и каждая её подкатегория. У каждого своя ссылка,
  которая собирается на глазах, пока меняешь страницу, размер, поиск, сортировку
  и галочки. Пустые поля в ссылку не попадают. Кнопка «Копировать» отдаёт готовый URL.
- **Акции и блог** — отдельными блоками.
- **Раздел «Аккаунт»**: регистрация с полем «Choose File» (отправляется настоящий
  `multipart/form-data`) и «Личные данные» — тот же POST, только с `id`.
  Полученный при регистрации `id` подставляется во вторую форму сам.
- **Одна форма на POST, PUT, PATCH и DELETE** для всех разделов каталога.
- **Справка «Как пользоваться API»** внизу — аккордеон: методы, адрес запроса,
  пагинация, фильтры, сортировка, поиск, JSON и `FormData`, регистрация и личные
  данные, коды ответа от 200 до 500.
- Тёмная и светлая темы, RU/EN, адаптив от 320 px.

## Разработка

На бесплатном тарифе Vercel деплой ограничен 12 serverless-функциями, поэтому
все эндпоинты обслуживает общая точка входа `lib/api-entry.js`, а маршрутизация
живёт в `lib/router.js` — тот же роутер использует локальный сервер.
`npm run check` следит, чтобы функций в `/api` не стало больше 12.

Путь запроса берётся сначала из параметра маршрута, а если его нет — из самого
`req.url`, поэтому эндпоинты работают и через catch-all `api/[...path].js`,
и через запасной `api/route.js`, на который `vercel.json` перенаправляет
`/api/:path*`.

```bash
npm install        # две зависимости: jimp (сжатие фото) и pg (нужен только при DATABASE_URL)
npm run dev        # http://localhost:3000 — API + страница документации
npm run generate   # пересобрать lib/dataset.json из описания каталога
npm run check      # проверить целостность данных и спецификации
npm run test:api   # 87 проверок по живым эндпоинтам, сервер поднимается сам
```

Пакет `pg` подгружается только тогда, когда задана `DATABASE_URL`: без неё
модуль не загружается вовсе. `jimp` подключается при первой загрузке
фотографии, поэтому холодный старт от него не тяжелеет.

Данные генерируются детерминированно: `lib/tree.js` (категории, подкатегории,
бренды, характеристики) + `lib/catalog.js` (общие справочники) →
`scripts/generate-dataset.js` → `lib/dataset.json`. Повторный запуск даёт тот же файл.

## Картинки

Картинки лежат в самом репозитории — внешних ссылок, которые могут отдать 404,
в данных нет ни одной.

- **Студийная фотография** — `assets/products/{slug}.jpg`, отдаётся статикой
  с CDN. Сейчас такие есть у 120 товаров из 780.
- **Рисованная карточка** — `GET /api/images/{slug}.svg`, фон в цвете категории,
  значок раздела и подпись. Её получают товары, для которых фотографии ещё нет,
  поэтому пустых картинок в каталоге не бывает.

Поле `image` товара указывает на фотографию, если она есть, иначе на рисованную
карточку. Когда в `assets/products/` добавляются новые файлы, достаточно
выполнить `npm run generate` — ссылки переключатся сами.

| Что нужно | Ссылка |
|---|---|
| Товар | `/api/images/{slug товара}.svg` |
| Категория | `/api/images/cat-{slug}.svg` |
| Подкатегория | `/api/images/sub-{slug}.svg` |
| Статья блога | `/api/images/post-{slug}.svg` |
| Второй ракурс | добавьте `?variant=2` |

В ответах API эти ссылки приходят уже абсолютными — их можно ставить в `src`
напрямую с любого домена.
